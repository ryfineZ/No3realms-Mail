# 分享链接预览说明

状态：已确认
日期：2026-06-16
范围：只读分享链接 `/share/:shareId` 及邮件正文链接

## 目标

分享链接发给别人时，聊天软件和浏览器收藏显示正确的邮箱分享标题，不能再显示旧的 Cloud Mail 名称。

## 非目标

本次不改变分享链接的权限、有效期、密码校验和邮件读取规则。

## 行为变化

访问 `/share/:shareId` 页面时，Worker 会在返回前端入口页之前写入分享页专用的标题、简介和社交预览信息。

显示规则：

- 链接里带 `email` 参数时，标题显示为“邮箱地址 的只读邮箱分享”。
- 链接里没有 `email` 参数时，标题显示为“站点名称 邮箱分享”。
- 简介只说明这是只读邮箱分享，不再使用项目默认介绍文案。
- 站点名称优先读取后台设置，读取失败时使用 `No3realms-Mail`。

## 影响范围

分享页 HTML 的标题和预览信息，以及分享接口返回的邮件正文链接属性。

## 验证方式

- 请求 `/share/test?email=test@example.com`，返回 HTML 应包含“test@example.com 的只读邮箱分享”。
- 返回 HTML 不应包含“Cloud Mail”。
- 普通首页仍正常返回前端入口页。

## 2026-11-18 邮件正文链接修复

分享页通过 iframe（内嵌网页窗口）展示邮件。原先没有指定链接打开位置，点击邮件中的登录按钮会在内嵌窗口加载目标网站。

点击邮件正文链接后应在新标签页打开，分享收件箱留在原标签页。分享服务统一设置链接的 `target="_blank"` 和 `rel="noopener noreferrer"`，保留原链接完整地址，包括查询参数和 `#` 后的内容。

处理范围涵盖普通链接、图片点击区域（`area`），以及 SVG（矢量图）中使用 `href` 或 `xlink:href` 的链接。统一覆盖邮件原有的打开位置和窗口引用设置。

邮件 iframe 的 sandbox（隔离限制）允许打开新标签页，新标签页使用正常网页权限。邮件正文继续禁用脚本和同源访问权限。两项弹窗权限需要同时设置，详见 [MDN 的 iframe sandbox 说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox)。

现有收件箱分享和单封邮件分享在读取内容时都应用此规则。

验证覆盖收件箱分享和单封邮件分享中的普通链接、图片点击区域、两种 SVG 链接属性、已有 target 和 rel 属性、登录链接参数保留、危险内容清理，以及分享页面的 iframe 权限配置。使用自动化测试和前端构建检查。
