# 发件地址一致性修复

日期为 2026-11-17。

## 目标

用户从 `a@sub.example.com` 发信或回复时，对方看到的发件地址和接收回复的地址均为 `a@sub.example.com`，发送记录也使用该地址。

## 非目标

收件规则、权限模型、发送额度和域名管理由各自模块负责。

## 行为变化

- 发给 Resend 的 `from` 始终使用当前发件邮箱的完整地址。
- Resend Token 优先使用邮箱域名自身的配置，其次逐级查找父域名配置。Token 用于 API 认证，发件身份由当前邮箱决定。
- 对方点击回复时，使用邮件中的原发件地址。
- 回复邮件继续携带 `In-Reply-To` 和 `References`，关联原邮件。
- Resend 拒绝发信时，将失败原因返回调用方，发送成功记录和发送统计在成功后写入。

## 使用条件

Resend 要求每个用于发信的子域名单独完成域名验证，调用凭证也需要有该域名的发送权限。子域名使用父域名 Token 时同样适用。[Resend 官方说明](https://resend.com/docs/dashboard/domains/introduction)

## 影响范围

后端 `/api/email/send` 的新建邮件、回复和转发流程，以及调用该接口的网页和 API 客户端。

## 验证方式

- 通过 Worker 的 `/api/email/send` 入口调用，拦截 Resend 请求并核对完整发件地址及成功记录。
- 覆盖域名自身配置、父域名配置、多级父域名配置及最近父域名优先的情况。
- 核对回复邮件的发件地址及原邮件关联信息。
- 模拟 Resend 拒绝发送，核对错误返回和发送记录、统计。
- 覆盖缺少发件凭证时的错误返回和站内邮件投递。
- 运行 Worker 全量测试。
